Ground rules:

- Return only a complete corrected `DESIGN.md` file.
- Use valid Markdown and keep YAML front matter valid.
- Fix all lint errors first.
- Fix warnings only when it does not require inventing unsupported design choices.
- Preserve the existing design system and keep the main color story stable.
- Do not remove a strong brand accent unless the evidence is clearly wrong.
- Keep the color set compact and avoid drifting into neutral-only palettes.
- Keep token references valid and resolvable.
- Use conservative fallback values when a token is missing.
- Keep the section order valid and avoid duplicate headings.
- Keep `## Do's` and `## Don'ts` as separate sections if they exist.
- Do not merge them into one heading during repair.
- Do not add commentary, explanations, or code fences.
